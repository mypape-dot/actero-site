## Scope and demonstrated checks

The automated browser harness reads only the **historical, already-public** functions `b5CountryConfig` and `showB5VariantGuide` from `main`. These functions are injected into an isolated browser test fixture: **no paid D1 script was downloaded, copied to GitHub, or read by the test.**

For each of **ES, IT, DE, AT, FR, GB, BE, NL, IE, CH** and each incident **DAMAGED / DATA_CHANGE**, the script checks the two modes on both Chromium desktop and WebKit mobile emulation. All **10 × 2 × 2 = 40** combinations passed.

Tests assert:

1. The visible heading names the expected country and incident.
2. The incident-specific first step is correct: keep/present the damaged passport vs. synchronize personal data in Romanian civil records.
3. Eight numbered steps and a personal document checklist render without JavaScript exceptions.
4. Residence-proof content and the linked source correspond to the selected country in the historical configuration.
5. If the user changes residence proof to **NO**, the missing-proof warning appears instead of an old confirmation.
6. If the user changes a data-change case from unsynchronized to synchronized, the old civil-record warning disappears and the updated confirmation is shown.

**A passed test confirms the script generates the expected elements; it does NOT prove source-link correctness, admissibility of the document, or legal accuracy.**

Operator's read-only D1 query (13 Oct) found in **both** `B5_DAMAGED` and `B5_DATA_CHANGE`: `evisa=NU`, `settled_status=DA`, `share_code=NU`. This is evidence of missing literal terms, not proof that every UK-specific instruction is wrong.
